# Phase 7 — District Officer Application Architecture & Operational Workflows

## 1. Executive Summary

Phase 7 implements the dedicated District Officer mobile application for MPLADS-AI (`MPLADS AI`). The application provides an authorized, operational interface for district nodal authorities, planning cells, and technical inspectors to monitor district development works, review ground evidence submitted by citizens, inspect server-side AI risk intelligence signals, track milestone SLA bottlenecks, and record on-site inspection outcomes.

Crucially, **data isolation is strictly jurisdiction-scoped**: a District Officer assigned to Araria, Bihar only accesses projects, pending evidence, and inspection itineraries within their statutory boundaries.

## 3. Jurisdiction Scoping & Security Model

```text
Authenticated Officer (Bearer JWT)
        ↓
FastAPI Security Dependency: require_role([UserRole.DISTRICT_OFFICER])
        ↓
Server-Side Jurisdiction Scope: jurisdiction_district = 'Araria', jurisdiction_state = 'Bihar'
        ↓
Authoritative Filtered Response (Projects, Evidence Queue, Assigned Route)
```

- **Zero Client-Side Security Trust**: Jurisdiction filtering is enforced server-side in `GET /api/v1/officer/dashboard` and `GET /api/v1/officer/projects`.
- **Privileged Inactivity Timeout**: Maintained Phase 4 15-minute inactivity session expiration for the `DISTRICT_OFFICER` role.

## 4. Operational Features & Workflows

### 4.1 Operational Dashboard (`index.tsx`)
- **Jurisdiction Metadata**: Displays designated district, state, and inspector unit ID (`insp-01`).
- **Operational Metrics**: `totalDistrictProjects`, `inProgressCount`, `completedCount`, `highRiskCount`, `pendingEvidenceCount`, `slaBottlenecksCount`.
- **Attention Queue**: Highlights pending citizen ground evidence awaiting review, high-risk anomalies, and SLA milestone delays.

### 4.2 District Projects Explorer (`projects/index.tsx` & `projects/[id].tsx`)
- Scoped to district boundary; supports search across titles and categories.
- Project Detail exposes comprehensive financial metrics, AI risk factor drivers (`costAnomalyScore`, `timeDelayScore`, `duplicateRiskScore`, `clusterDensityScore`), milestone aging status, and direct triggers to review evidence or record site inspections.

### 4.3 Evidence Review Console (`evidence/index.tsx`)
- Evaluates citizen submissions with location verification status (`LOCATION_VERIFIED` vs `LOCATION_INCONSISTENT`), distance from project base in meters, and capture timestamps.
- Interactive decision actions: **Accept Evidence**, **Reject Submission**, and **Request More Information** with remarks via `POST /api/v1/officer/evidence/{id}/review`.

### 4.4 Inspection Itinerary & Field Updates (`inspections/index.tsx`)
- Displays prioritized itinerary stops generated by `inspection_engine` ordered by priority rank and distance.
- Form to submit official on-site inspection findings: Work ID, status (`COMPLETED`, `IN_PROGRESS`, `ANOMALY_FOUND`), field observations, and estimated physical progress (%).

### 4.5 SLA Bottleneck Monitoring (`sla/index.tsx`)
- Identifies projects with milestone delay ratios exceeding benchmarks.
- Tracks responsible nodal authority and aging duration.

## 5. API Endpoints & Contracts

| Feature | Method & Endpoint | Auth Required | Required Permission |
| :--- | :--- | :--- | :--- |
| **Officer Dashboard** | `GET /api/v1/officer/dashboard` | Bearer JWT | Role: `DISTRICT_OFFICER` |
| **District Projects** | `GET /api/v1/officer/projects` | Bearer JWT | Role: `DISTRICT_OFFICER` |
| **Evidence Review** | `POST /api/v1/officer/evidence/{id}/review` | Bearer JWT | `evidence:review` |
| **Inspection Update** | `POST /api/v1/officer/inspections/{id}/update` | Bearer JWT | `inspections:update` |
| **Inspection Plan** | `GET /api/v1/optimizer/plan` | Public / Auth | None |
| **SLA Detail** | `GET /api/v1/sla/bottleneck/{id}` | Public / Auth | `sla:read` |

## 6. Bilingual Localization & Accessibility

- **Localization (`en-IN` & `hi-IN`)**: Every officer string is localized under the `officer` namespace in `en-IN.ts` and `hi-IN.ts`. Zero hardcoded user-facing strings.
- **Accessibility**: Explicit `accessibilityRole`, `accessibilityLabel`, and `accessibilityState` across all buttons, status badges, metric boxes, and forms. Minimum 44px hit targets preserved throughout.
